# Consent Flows sandbox

Open `index.html` on a static host or run `npm start` locally. Enter a public API key and a published Consent Flow ID, choose the Flow publication and Didomi platform environment, then **Apply and reload**.

Example (replace placeholders with a published Flow):

```text
index.html?apiKey=YOUR_PUBLIC_KEY&flow_id=YOUR_FLOW_ID&environment=staging&country=US&region=CA
```

## Workspace

- **Setup:** a section navigation column and collapsible groups for Flow details, delivery overrides, SDK URL overrides, rules context, and advanced configuration. Apply and reload opens the test tab.
- **Test:** Widget ID and Layer name sit beside Show widget. Change either and click Show widget without reloading; leave both blank to use Flow rules. These selections are preserved in share links. The tab uses six numbered, collapsible sections: Widget controls, Consent strings, Current consent state, TCF and GPP API diagnostics, Data layer and Google Consent Mode, and URL-pattern test. Widget controls and Consent strings start open; the other sections start collapsed.
- **Configuration:** an expandable tree and complete plain JSON view of `Didomi.getConfig()`, with refresh and copy controls. Runtime overrides are included; use browser Network for the original response. Tree branches render lazily; large collections show 100 entries at a time. Expand sections opens up to 1,000 sections per click. Plain JSON and Copy JSON always include the complete response.
- **Troubleshoot:** the Console checklist, setup findings, and captured runtime messages. After both a public API key and Flow ID have been supplied and a load has been attempted, SDK loading failures, readiness timeouts, missing widgets/assets, failed SDK actions, and newly captured runtime errors select and focus this tab automatically. Empty or incomplete troubleshooting links start on Setup; the Troubleshoot tab remains available manually. Input validation stays beside the Setup controls.

Tabs support keyboard arrows, Home and End. The fragments `#setup`, `#test`, `#config`, and `#troubleshoot` open the relevant workspace; previous config and troubleshooting section anchors are also supported.

In Setup → SDK configuration and tools, **Apply custom JSON** sits directly above the custom JSON editor. Set it to **On**, then click **Apply and reload** to apply the override. **Off** keeps the JSON in the share link without applying it.

Native modal widget dialogs can cover the floating Hide preview button regardless of its z-index. Press **Alt+H** (**Option+H** on Mac) to invoke the same hide action and return to the sandbox controls. This dismisses the preview without recording a consent choice or resetting consent.

## Query parameters

| Parameters                                                                                                                                         | Behavior                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apiKey`, `flow_id`                                                                                                                                | Required. Loader path `/{apiKey}/loader.js?target_type=flow&target={flow_id}`. Also accepts incoming `target_type=flow&target=…` and normalizes it to `flow_id`.                                                                                                                      |
| `environment`                                                                                                                                      | Flow publication: `production` (default, omitted from loader URL) or `staging`.                                                                                                                                                                                                       |
| `sdk_environment`                                                                                                                                  | Didomi platform environment: selects SDK and configuration infrastructure. `production` and `preprod` use production configuration data; `staging` uses staging configuration data. Flow publication selects the version within that data store.                                      |
| `platform`                                                                                                                                         | Browser test platform: `web` (default) or `ctv`. Use a matching published Flow. AMP is explicitly unsupported by the Flow embed generator; native apps require their native SDK.                                                                                                      |
| `country`, `region`                                                                                                                                | Loader geo overrides, also set on `window.didomiConfig.user`. Region requires country.                                                                                                                                                                                                |
| `regulation`                                                                                                                                       | Loader regulation override, e.g. `gdpr`, `cpra`. Resolution still requires that regulation in the deployed Flow.                                                                                                                                                                      |
| `lang`                                                                                                                                             | Loader language request. Single-language delivery only applies when the config enables `languages.requestedOnly`. This does not force the SDK display language.                                                                                                                       |
| `brand`, `brand_version`                                                                                                                           | Override the response's brand reference; a version requires a brand. This can replace the published theme snapshot with IDs only, affecting widget styling. Omit both to keep the published snapshot; the stored Flow is unchanged.                                                   |
| `opts`                                                                                                                                             | Only `gvl` is offered: explicitly include IAB Global Vendor List data in `loader.js`. Automatic omits `opts`; GDPR/IAB configurations normally include this data already. Unrecognized or JSON-endpoint-only tokens in older share links are rejected rather than silently forwarded. |
| `ts`                                                                                                                                               | CDN cache-key value. Change it to bypass an existing cached response.                                                                                                                                                                                                                 |
| `didomiConfig`                                                                                                                                     | Native SDK URL JSON object, filtered by the SDK to the allowlist below.                                                                                                                                                                                                               |
| `didomiConfig.notice.enable`, `didomiConfig.notice.showDataProcessing`, `didomiConfig.app.alwaysDisplayActionButtons`, `didomiConfig.sync.enabled` | Native boolean URL overrides. Blank inherits, `false` explicitly disables.                                                                                                                                                                                                            |
| `didomiConfig.experiment.group`, `didomiConfig.user.externalConsent.value`                                                                         | Native SDK URL overrides; interpreted by the SDK as JSON when parseable, otherwise strings.                                                                                                                                                                                           |
| `didomiConfig.app.vendors.iab.version`                                                                                                             | Native numeric SDK URL override.                                                                                                                                                                                                                                                      |
| `didomi_country`, `didomi_region`                                                                                                                  | Native runtime geo overrides. Distinct from loader selection; the inspected SDK reads two-letter values and gives URL geo priority.                                                                                                                                                   |
| `commit_hash`                                                                                                                                      | Sandbox setting for `window.didomiConfig.app.sdkVersion`: full 40-character commit or `latest`. The loader prefers an existing remote config SDK pin over this page value.                                                                                                            |
| `organization_user_id`, `age`, `page_category`, `attributes`                                                                                       | Sandbox rule context: maps to `user.organizationUserId`, `user.age`, `pageCategory`, `user.userContext.attributes`. Attributes must be a JSON object. Setting an organization user ID can also engage configured SDK identity/sync behavior.                                          |
| `config`, `apply_conf`                                                                                                                             | Sandbox full-config override: UTF-8 base64 JSON object; applied to `window.didomiConfig` only with `apply_conf=1`. Explicit sandbox inputs override conflicting JSON values. Invalid JSON blocks loading even when disabled so bad share links are visible.                           |
| `widget_id`, `layer_name`                                                                                                                          | Sandbox widget action settings: `Didomi.widgets.show({widgetId, layerName})`. Empty values are omitted; empty options let Flow rules select the widget. These are not native loader query parameters.                                                                                 |
| `gpp_stub`                                                                                                                                         | `1` loads the existing local GPP stub **before** SDK startup. The TCF bootstrap is always installed.                                                                                                                                                                                  |

Native `didomiConfig.*` URL fields take precedence over the aggregate native `didomiConfig` URL JSON and are filtered by the SDK to its seven allowed properties. They are kept in the **page** URL, not forwarded to `loader.js`. The custom sandbox JSON applies before the SDK's native URL overrides. Unknown page parameters are preserved in share links but not forwarded to the loader.

Changes update the share URL with `replaceState`; SDK configuration and widget action settings take effect on reload. The page shows the generated loader URL and effective window config, and reports loader failures or a 20-second readiness timeout. A dedicated **Loaded SDK configuration** section automatically displays the full pretty-printed `Didomi.getConfig()` response on SDK readiness and after widget actions. **Refresh loaded config** reads it again, and **Copy JSON** copies the full response (with text-selection fallback if clipboard access is unavailable). The JSON panel scrolls independently within the Configuration tab. A loader returning HTTP 200 is not proof that a matching Flow was resolved: the service can fall back to an API-key-only loader. Verify the loaded regulation and widget config.

GPC comes from `navigator.globalPrivacyControl`. Consent status comes from the SDK consent store; use **Reset status** on Setup or Test for a fresh consent state. Both buttons call `Didomi.reset()` and reload. The SDK manages its consent cookies and storage; current URL settings and overrides remain in effect. This does not invalidate CDN/browser caches; change **Cache key** when a fresh config response is needed. URL-pattern rules use `window.location.pathname`, so rules targeting another site's pathname will not match this sandbox path. No fabricated native query parameters are provided for GPC, consent status, or pathname. To test rule selection for another path, use the URL-pattern tester described below.

## Loader options

This page loads `/{apiKey}/loader.js`; it does not issue a separate config JSON request. `Didomi.getConfig()` reads the initialized SDK’s configuration. The loader already includes the selected configuration in its JavaScript response.

**Automatic** omits `opts` and lets the loader decide whether vendor-list data is needed. **Include IAB Global Vendor List (gvl)** sends `opts=gvl`, requesting that data even when the selected regulation would not normally include it. This can help investigate IAB vendor-list availability with a non-GDPR location. GDPR or IAB-enabled configurations normally include it already, so selecting it may produce no visible difference. It does not enable TCF, change its version, or select staging/production. No other `opts` choices are currently exposed for Web/CTV.

The field has a tooltip and an accessible **Examples and behavior** disclosure. Shared links containing unrelated options are blocked with a clear correction message. Native SDK URL overrides and sandbox runtime controls remain separate from loader request parameters.

## CTV UI preview

In **Setup → Flow and deployment**, keep **Platform = web** and enable **Force CTV UI** to test the SDK’s CTV UI behavior against a web configuration. The sandbox parameter `ctv_ui=1` applies `window.didomiConfig.app.ctvEnabled = true` before SDK loading. It is not a native SDK URL parameter and is not forwarded to the loader; the selected platform stays unchanged. Leaving it off preserves the published config’s behavior.

This does not redesign a web widget, change the published Flow platform, or force an older SDK build. The SDK may display a CTV fallback notice when a Flow widget cannot render. The runtime summary reports notice visibility separately from widget visibility so this does not look like a successful widget test. Publish compatible CTV content in Console for a full TV integration test. The SDK CTV layout is designed for a TV viewport; use a 16:9 viewport for a representative preview. Sandbox styles are scoped to its own root so they do not affect SDK content. A floating Hide preview button dismisses the notice, preferences, or widget UI without accepting consent or resetting user status.

## Scope of troubleshooting

While a preview is visible, its host fills the viewport above the sandbox tabs and form controls. Use Hide preview or Alt+H (Option+H on Mac) to return to the workspace. This applies to both Web and CTV configurations and keeps the widget's full-screen layout separate from the testing controls without changing the published widget.

If Show widget fails or finishes without displaying a widget, a dialog explains the problem and offers a Read troubleshooting button. This opens tab 4, Troubleshoot, and focuses the Troubleshooting heading. Close or Escape dismisses the dialog so you can adjust settings and try again.

Diagnostics use the config publicly returned to this browser and messages observed during the current page load. They are heuristic checks, not a full schema validator or an inspection of your Console account. Start in Console: review Flow regulation coverage, assigned widgets and display rules, saved brand settings, and successful publication to the selected environment. The page cannot confirm unsaved drafts, permissions, or publication status.

Setup checks cover missing widget assets, missing or inconsistent widget references, incomplete brand references or snapshots, missing regulation or API key values, and display-rule conditions that may need review in Console. They do not assume all optional config sections are required. Recommendations prioritize Flows, Regulation Manager, Brand Manager, the widget editor, and successful publication. A widget version reference without a display asset does not establish an editor mistake. If the assignment and successful publication are confirmed, the guidance directs users to support for investigation rather than requiring arbitrary widget edits.

### Published widget artifacts and brands

Current widget definitions carry `versionId`, `defaultLanguage` and `artifacts.web[language]`. Each web entry contains a `modern` URL and a `legacy` object with `url` and `globalName`. Native layout artifacts do not supply web display assets. The SDK uses its exact display language when present, then the widget’s default language; it does not construct asset URLs from IDs. The sandbox uses the observed `#didomi-host` language and loaded SDK script path for checks. Requested `lang`, Platform and Force CTV UI are not proof of the actual SDK language or build. When those observations are unavailable, checks inspect published candidates without claiming which one is active. Runtime details include the observed context and asset candidates. Older `bundleUrl` / `bundleUrls` configs remain inspectable, with an informational compatibility finding; those fields are not a fallback for a malformed `artifacts` map.

The published `brand` carries its reference and a snapshot of the brand profile plus `brand_config` theme data. The SDK passes this object to widget bundles. A reference alone does not prove that theme data is available. The loader’s `brand` / `brand_version` query override can replace the snapshot with a reference, so clear these overrides and compare the published configuration if styling is missing. The sandbox never fetches or invents brand snapshots or artifact URLs.

If a widget behaves differently in normal and private browsing after a release, a cached loader may point to an SDK expecting an older config format. Try a new **Cache key** or clear the browser cache and reload. **Reset status** resets consent, not the loader cache. CDN invalidation on SDK deployment is an infrastructure concern and cannot be fixed by this page.

Runtime capture starts before the SDK and main page module load. It records console warnings/errors while preserving the original console calls, page exceptions, unhandled promise errors, failed resource loads, and CSP violations. Identical messages are grouped; at most 100 distinct records are retained in memory, with message/detail length limits. Clear captured messages removes only runtime evidence, not config findings. Messages are neither sent nor included in share links.

Technical evidence is available for support and site developers. Cross-origin restrictions may hide error details and resource events do not reveal HTTP response status. No customer presets, private repository references, internal service descriptions, or issue-tracker links are included.

### Empty or missing display rules

When a delivered config includes widgets but has `rules: []` or no `rules` property, troubleshooting shows a warning. Some SDK builds skip widget initialization in this case, even with a valid default widget and bundle URL. The SDK itself can still become ready and display a legacy fallback notice; widget display or Show widget can fail. This is a possible cause, not a declaration that the config is invalid or that the behavior is intended. Review the configured rules and publication in Console; for an intentional default-widget-only Flow, confirm expected behavior and SDK version with support rather than adding an arbitrary rule.

## Consent strings

On tab 2, Consent strings reads `Didomi.getCurrentUserStatus()` after SDK readiness and displays its `consent_string` (TC) and `gpp_string` values. Snapshots load automatically on SDK readiness and refresh after consent changes and preview-close events, with short follow-up reads for delayed framework encoding and storage writes. Refresh consent strings remains available for a manual check. Reads do not modify consent, and older asynchronous results cannot overwrite a newer snapshot. Copy buttons preserve the complete strings. Missing values have framework setup guidance; failed reads clear previous values so stale strings cannot be mistaken for the latest result.

Both IAB decoder links (TC and GPP) open the [IAB decoder](https://iabgpp.com/#) in new tabs with the displayed string after `#`. Refreshing updates those links; missing values or failed reads clear them back to the blank decoder so old strings are not reused. A returned string alone does not indicate agreement to all purposes or vendors. DCS is also available in this section as a saved browser snapshot, read separately from the configured cookie or local storage key (default `didomi_dcs`). The complete value, including signature parts, is preserved for copying. If cookie and local storage values differ, the cookie is shown with an explicit warning. DCS storage/config read errors clear its field without hiding TC/GPP results. The [Didomi DCS decoder](https://dcs-decoder.didomi.io/) opens in a new tab with the complete displayed value URL-encoded in `?dcs=...`, including any signature. Unlike the IAB fragment links, this query parameter is sent to the decoder server when opened. Missing values or failed reads reset the link to the blank decoder.

## Current consent state

On Test, expand **Current consent state** to inspect the same `Didomi.getCurrentUserStatus()` snapshot used by Consent strings. Both refresh on SDK readiness and supported consent/preview-close events; either Refresh button reads both views. The inspector shows the capture time, regulation, whether the SDK requests consent collection, created/updated values, purpose/vendor summaries, and a raw SDK snapshot with all returned fields, including optional state flags and strings. A pending refresh marks the previous snapshot stale and disables copy; failed, timed-out, unavailable or malformed reads clear previous results. A manual refresh remains available when SDK events are unavailable.

Tables distinguish enabled, disabled and unknown (including missing or non-boolean enabled values). IDs remain exactly as returned, including namespaces. Names/namespace metadata are resolved through public lookups over already-loaded SDK data, with exact-ID custom-config fallback; unavailable names retain the IDs. Some SDK builds return translation keys as names; these are shown as returned. Missing status maps differ from empty maps. An empty map, a default enabled value, an essential purpose, bot exemption, or `regulation=none` does not establish explicit agreement. The snapshot can differ from pending edits in an open widget.

`window.didomiState` is sampled separately at the same capture time as a **tag-manager projection**, which can differ from the SDK response or be absent. The inspector does not install a tag manager or execute getters on the projection. DCS continues to come from the existing configured-storage reader; there is no competing DCS source.

Filter by ID, name, namespace or effective state. Tables render 100 rows at a time and offer **Show next 100**. Filtering affects only displayed rows. Raw snapshots and **Copy consent snapshot** retain captured data; copy includes identifiers and consent strings when returned and labels each source. Data stays in browser memory and never enters share links. Snapshots omit accessors, mark circular/repeated references, and are bounded to 100,000 visited values, 10,000 properties per object, depth 16, 20,000 characters per string and an approximate two-million-character budget. Any limits reached are reported; copied data is not claimed complete when truncated.

## URL-pattern testing

On tab 2, expand **URL-pattern test**, enter a pathname such as `/checkout`, and click **Check path rules**. The sandbox calls `Didomi.widgets.getApplicable({ currentUrl: pathname })`, overriding only the path for that query and retaining the SDK’s other current context. It displays the selected rule/widget, default fallback, or unavailable result. This requires an SDK version that exposes `widgets.getApplicable`.

This checks rule selection without navigating, rendering a widget, or changing the SDK’s automatic selection. Automatic display and **Show widget** still use the real sandbox pathname. Other Setup changes must be applied first. The test path is temporary and is not included in share links. A matching rule does not prove that the widget’s published assets can render. Full page behavior should also be checked on the intended site path.

## Data layer and Google Consent Mode diagnostics

The Test tab includes a read-only view of data layer entries and Google Consent Mode (GCM) commands. It observes the default `dataLayer`, the GCM layer named in `integrations.vendors.gcm.dataLayerName`, and the tag-manager layer named in `tagManager.dataLayerName`. It does not create queues, enable GCM, load Google tags, or send diagnostic data anywhere.

The panel shows the effective integration settings, selected regulation and group, browser GPC, and loaded SDK script. The signal table keeps configured defaults, the last observed default command, and the last observed update separate. It does not infer denied consent from a missing signal. Stored choices can result in an update at startup; opt-in configurations with defaults off can legitimately emit no default. Mixed-group defaults, GPC, and TCF-managed advertising also affect which signals are expected. These notes are checks to try, not a replacement for inspecting the actual commands from the loaded SDK build.

Capture starts before the SDK loader. Existing and newly discovered queues are sampled, and their entries are labeled with an observation time rather than an original event time. Where possible, new pushes are wrapped to capture them immediately while preserving the original receiver, return value and errors. Late queue creation, queue replacement and read-only push methods are checked periodically; sampling can miss intermediate or overwritten entries. Shared queues are observed once. The viewer retains at most 200 entries and limits snapshot depth, property counts and text sizes; truncation is marked.

Use the filter to search layer names, commands or payload text. Copy filtered diagnostics includes the effective configuration context and matching entries; review it before sharing because arbitrary data layer values can contain visitor information. Clear diagnostic view discards only the captured history, leaving real queues and consent choices intact. Nothing is saved to browser storage or added to share links. Observing a command does not prove that Google tags loaded or consumed it.

When the SDK confirms a consent choice from before the current page load for the active regulation and reports that status does not currently need to be collected, an informational banner offers Reset status and Show widget again. The banner does not treat a new user ID, default enabled values, or regulation=none as a stored choice. It describes the loaded SDK context rather than claiming a separate consent record exists for each widget. Reloading without resetting still loads available strings and data-layer commands automatically. A missing or inapplicable framework string is explicitly labeled, not fabricated.

The local development server disables file caching so a refreshed page cannot keep an older consent-string module alongside new HTML. This setting applies to local preview only.

## TCF and GPP API diagnostics

On Test, expand **TCF and GPP API diagnostics**. Loading a configured Flow starts independent read-only ping and event-listener probes. Function existence alone is not readiness: startup stubs, loading responses, successful responses, ready status, evidenced non-applicability, callback errors, absent APIs and initial timeouts are reported separately. Framework availability does not prove consent or legal compliance. Explicit loaded-config disable flags are shown separately from observed API state; missing flags remain unknown.

TCF uses `ping`, `addEventListener` and `removeEventListener` at API version 2; it does not use the deprecated `getTCData` chain. GPP uses its corresponding ping/event/removal commands. Raw responses include callback success flags, timestamps, available version metadata, strings and parsed sections. GPP header-only `DBAA` with ready signal and applicable sections `[-1]` is treated as not applicable, not a failed probe. Displayed versions are observed values, not hard-coded policy labels.

Each initial callback has a five-second timeout. Events can subsequently update a timed-out probe. Startup API replacement is checked every 500 ms for 20 seconds; **Probe APIs** retries later. Refresh, **Clear view** and page exit request listener removal. Late registration callbacks from old probes can clean up their IDs but cannot overwrite the current view. A queued startup stub's late registration is removed through its replacement API. Clear stops automatic discovery until an explicit refresh.

Each framework retains at most 30 bounded observations. **Copy framework report** includes returned identifiers and consent strings and uses the existing bounded, accessor-safe snapshot utility. Raw history is local to browser memory and never enters share URLs. The diagnostic reads the existing shared SDK snapshot for string comparisons, without adding another user-status or DCS reader. Comparisons are labelled stale while that snapshot is refreshing. Differences can reflect asynchronous framework encoding and callback timing; refresh both views before diagnosing a mismatch. Browser GPC is shown as observed, without changing it or inferring compliance. These controls never enable a framework, alter consent, reset status or load vendor lists.
